# Upgrade Appsmith Versions

This page explains how to update your self-hosted Appsmith instance to the latest version.

## Prerequisites

Before you update, make sure that:

1. You have at least 2 GB of free storage for the backup and update.
2. Your embedded or external MongoDB server runs version 5.0 or later. To upgrade MongoDB, check the [supported platforms](https://www.mongodb.com/docs/manual/administration/production-notes/#platform-support) and follow the [MongoDB replica set upgrade guide](https://www.mongodb.com/docs/manual/release-notes/5.0-upgrade-replica-set/).
3. You have a backup of your Appsmith instance. To create one, follow the [Backup instance guide](/getting-started/setup/instance-management/appsmithctl/#backup-instance).

## Required upgrade checkpoints

Before upgrading a self-hosted instance to **v2.6 or later**, install **v2.5.2** and complete the **Workflow Engine Transition** checkpoint. Sign in as an instance administrator and open **Admin Settings → Instance → Admin central** to review and acknowledge the checkpoint. Do not proceed to v2.6 or later until it is complete. See [Upgrade checkpoints](/getting-started/setup/instance-management/upgrade-checkpoints) and [v2.5.2 workflow engine transition](/getting-started/setup/instance-management/upgrade-checkpoint-v2.5.0-temporal) for details.

## Update Appsmith

Select your platform and follow the steps to update Appsmith to the latest version:

<Tabs queryString="current-platform-type">

<TabItem label="Docker" value="docker">

These instructions apply to Docker-based platforms, such as Docker standalone and AWS AMI.

:::caution Important
Some versions are checkpoints that you must install before you upgrade further:
 - If your current version is earlier than v1.9.2, follow the steps in [Upgrade to v1.9.2](/getting-started/setup/instance-management/upgrade-to-checkpoint-version#upgrade-to-v192) before you update to the latest release.
 - If your current version is later than v1.9.2 but earlier than v1.96, follow [Upgrade to v1.96–v1.99](/getting-started/setup/instance-management/upgrade-to-checkpoint-version#upgrade-to-v196v199) before you upgrade to v2.0 or later.
 - Before upgrading to v2.6 or later, install **v2.5.2** and complete the checkpoint in [Admin central](/getting-started/setup/instance-configuration/admin-central).
:::

:::caution Upgrading from a version earlier than v2.4
If you use SAML SSO and your `docker.env` sets `APPSMITH_KEYCLOAK_DB_URL` but not `APPSMITH_KEYCLOAK_DB_DRIVER`, add `APPSMITH_KEYCLOAK_DB_DRIVER=h2` before you upgrade. Without it, SAML SSO login can fail with a 502 error after the upgrade. See [SAML SSO login returns 502 after upgrading to v2.4 or later](/help-and-support/troubleshooting-guide/upgrade-migration-errors#saml-sso-login-returns-502-after-upgrading-to-v24-or-later).
:::

1. Find your Appsmith installation directory:
   ```bash
   docker inspect -f '{{ (index .Mounts 0).Source }}' <APPSMITH_CONTAINER_ID>
   ``` 
2. Choose the Appsmith version you want to run.

   Find its release tag on [GitHub](https://github.com/appsmithorg/appsmith/releases).

3. Open `docker-compose.yml` in that directory and set the `image` for the Appsmith service to a pinned tag, for example:

   ```yaml
   image: index.docker.io/appsmith/appsmith-ee:<version>
   ```

   If you use the Community Edition, replace `appsmith-ee` with `appsmith-ce` and keep the same `:<version>` suffix.

4. Pull the image and restart the container. The new container runs the version set in `docker-compose.yml`.

   ```bash
   docker-compose pull && docker-compose rm -fsv appsmith && docker-compose up -d
   ```

</TabItem>

<TabItem label="Kubernetes" value="kubernetes">

:::caution Important
If your current version is earlier than v1.9.2, follow the steps in [Upgrade to v1.9.2](/getting-started/setup/instance-management/upgrade-to-checkpoint-version#upgrade-to-v192) before you update to the latest release.
:::

> **Note**: These instructions assume you followed the [Kubernetes installation guide](/getting-started/setup/installation-guides/kubernetes) exactly. If you changed any defaults, such as the Helm release name or namespace, adjust the commands to match.

1. Choose the latest Appsmith version.

   Find the latest release tag on [GitHub](https://github.com/appsmithorg/appsmith/releases).

2. Update the local Helm chart repository index:

   ```bash
   helm repo update appsmith-ee
   ```

3. Upgrade the Helm release to the new version:

   ```bash
   helm upgrade appsmith-ee appsmith-ee/appsmith -n appsmith-ee \
     --reset-then-reuse-values --set image.tag=<version>
   ```

   This command upgrades the Helm chart to its latest version and sets the Appsmith image to `<version>`. The `--reset-then-reuse-values` flag keeps the values of your current release and applies the defaults of the new chart version.

   If you manage `values.yaml` in source control, set `image.tag` in that file and run the command with `-f values.yaml` instead of `--set image.tag=<version>`.

4. If Helm rejects the upgrade with `values don't meet the specifications of the schema(s)`, a value in your release is not compatible with the latest chart version. Helm makes no change to the release. Do one of these:
   - Update the values that the error lists, then run step 3 again.
   - Keep your current chart version and update only the Appsmith image:

     ```bash
     CHART_VERSION=$(helm get metadata appsmith-ee -n appsmith-ee | awk '/^VERSION:/ {print $2}')
     helm upgrade appsmith-ee appsmith-ee/appsmith -n appsmith-ee \
       --version "$CHART_VERSION" --reuse-values --set image.tag=<version>
     ```

2. Select the cluster that contains the container instance you want to update.
3. Stop the task. ECS automatically deploys a new task.
4. Verify that the updated version is running.

## Troubleshooting

If the update fails, roll back to the previous version by following the [Restore instance](/getting-started/setup/instance-management/backup-and-restore/restore-instance) guide. If the problem persists, contact support using the chat widget in the bottom-right corner of this page.
